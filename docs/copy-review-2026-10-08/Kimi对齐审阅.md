# Kimi 第二轮对齐审阅

以下为该模型对汇总候选稿的原始意见。具体采纳与不采纳原因见《三模型对齐记录》。

## 1) 必须修正的问题（6项）

1. **R080 添加组别 → 显示灯组** 与 R052/R075（管理入口/弹窗标题）重名但操作不同。推荐改为「显示此组」，原因：不同操作重名，用户无法区分入口与执行动作。
2. **R103 启动异常提示 → 无法启动** 说明漏掉「保留错误详情」。推荐说明改为「保留错误详情，点“刷新面板”重试」，原因：事实12要求动态错误细节不得隐藏，原文模板含 {错误}，属内容丢失。
3. **R024 预设项模板 → 默认** 未注明名称变量保留。推荐说明补「预设名称完整保留，仅简化标记」，原因：避免被读成删除 {名称} 字段。
4. **R011 未连接状态说明**「预设可在电脑保存；调光需先连接」基本合规，但建议补「灯组操作需连接」语义，推荐「预设可保存到电脑；灯组调节需先连接」，原因：事实2明确灯组操作离线禁用，现说明偏窄易误读为其他离线可用。
5. **R057 与 R059 均候选「数字」**。推荐 R057 改「数字值」，原因：同区域近似提示重名，虽属不同模式仍易混淆；2-5字内可行。
6. **R041 一起调光** 说明「调整面板内已开启灯组的数值」可，但「已开启」未排除 OFF 组的边界在 X003「关闭」体系下建议统一表述为「未关闭灯组」，原因：与事实7「可见非OFF组」措辞对齐，避免「开启」被理解为电源。

## 2) 六组核心命名逐项判断

- **同步 → 应用到设备**：可采用。明确单向发送，规避「同步=双向」误解，与事实8一致。
- **关闪 → 关闭闪光**：可采用。名称2-5字，说明「仅关闭面板内灯组，再点可恢复」与事实5吻合。
- **灯组管理 → 显示灯组**：建议调整。入口名与 R080 添加动作重名，建议入口改「灯组显示」，执行改「显示此组」。
- **造型灯 → 预览灯**：可采用。全局「预览灯开关」与组内「预览灯」分层清楚，且未改成闪光灯/电源，符合事实4。
- **回电音 → 提示音**：可采用。全局「声音开关」、组内「提示音」分字段成立，说明「回电完成时提示」限定了场景。
- **M/TTL/OFF → 手动/自动/关闭**：可采用。与事实6逐一对应，未新增频闪或曝光补偿承诺。

## 3) 阻止采用的事实缺口

有，两处仍为待确认，阻止「整体定稿」但不阻止其余条目采用：

- **默认预设命名（R024/R028/R029/R117–R120/X018）**：事实是须手动载入、不开机自动应用，「默认」与「常用」取舍未定，相关条目须保持待确认状态，不能写成定稿。
- **页脚兼容与共享（R049）**：XPro II/X2T 兼容及多机共享无实机证据，只能保留待确认，不得扩写或删改承诺。

除上述外，候选表无与已核对事实冲突的错误功能承诺，版本号、档位数值、错误详情保留方向正确。
